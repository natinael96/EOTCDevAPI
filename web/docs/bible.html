Bible

The layer the Gitsawe references point into: the canon, each book's structure under the Ethiopian versification, a citation parser that reads printed Ge'ez references, and an honest boundary around verse text.

GET/v1/bible/books

The canon as book metadata: 93 book records of the EOTC 81-book counting tradition, as divided by the am-1980 edition.

ParameterRequiredValues
testamentNoold, new
sectionNoGospel, PaulineEpistle, Deuterocanonical, …
 
$ curl "…/v1/bible/books?testament=new"
{
  "versification": "am-1980",
  "count": 35,
  "books": [
    { "id": "MAT", "order": 55, "slug": "matthew",
      "section": "Gospel",
      "names": { "english": "Matthew", "amharic": "የማቴዎስ ወንጌል",
                  "amharicAbbreviation": "ማቴ" },
      "chapters": 28 }, …
  ]
}
GET/v1/bible/books/{id}

One book in detail, addressed by USFM-style ID (JHN), slug (psalms), or any of its names in any script. Adds verseCounts, the per-chapter verse totals, labeled with the versification they come from; Ethiopian versification differs from Western editions, so the label is part of the contract.

$ curl …/v1/bible/books/psalms
{ "id": "PSA", "names": { "amharic": "መዝሙረ ዳዊት" },
  "chapters": 150, "versification": "am-1980",
  "verseCounts": [6, 12, 8, …] }
GET/v1/bible/editions

The editions registry: identity, publisher, canon, license, and source for each edition the API knows (am-1980, gez-1980, both from the EOTCOpenSource 80-weahadu project, CC BY-NC-ND 4.0).

GET/v1/bible/parse

The citation parser the Gitsawe compiler itself uses, exposed. It reads printed Ge'ez citations, Amharic book names with Arabic or Ge'ez numerals, and Latin references, and resolves the book with the same homophone folding as feast search:

$ curl "…/v1/bible/parse?q=ዮሐንስ ም· ፫ ቍ ፲፮"
{
  "resolved": true,
  "book": { "id": "JHN", "confidence": "partial" },
  "chapter": 3, "verseStart": 16, "verseEnd": null,
  "withinBounds": true
}

$ curl "…/v1/bible/parse?q=መዝሙረ ዳዊት ፻፵፩ ቍ ፮ – ፯"   # a real Gitsawe ምስባክ citation
{ "book": { "id": "PSA" }, "chapter": 141, "verseStart": 6, "verseEnd": 7 }

$ curl "…/v1/bible/parse?q=1 Peter 2:9"
{ "book": { "id": "1PE" }, "chapter": 2, "verseStart": 9 }
  • withinBounds checks the reference against the edition's real chapter and verse counts; an impossible citation parses but reports withinBounds: false.
  • confidence is exact for a full name match and partial for an unambiguous shorthand; an ambiguous label (a bare ዮሐንስ could be the Gospel or an epistle) resolves only when the citation context or a numeral disambiguates it.
  • ፍጻሜ ምዕራፍ ("to end of chapter") citations return verseEnd: null, toEndOfChapter: true.
GET/v1/bible/{edition}/{book}/{chapter}

The chapter endpoint always validates the reference and returns its structure. What it will not do, on the public deployment, is serve the verse text: the available editions are CC BY-NC-ND and the runtime is MIT, so text stays out.

$ curl …/v1/bible/am-1980/JHN/3
{
  "edition": { "id": "am-1980", "license": "CC-BY-NC-ND-4.0" },
  "book": { "id": "JHN" },
  "chapter": 3,
  "verseCount": 36,
  "verses": null,
  "textAvailable": false,
  "reason": "Verse text is not bundled with the public MIT runtime; the edition is CC BY-NC-ND."
}

Serving text on your own deployment¶

Self-hosted Python deployments whose operator holds a licensed copy of an edition can activate text serving. Nothing ships in the repository; the opt-in is explicit:

$ export EOTC_BIBLE_TEXT_DIR=/path/to/bible-data   # laid out like data/bible/
$ ./.venv/bin/uvicorn eotc.api:app --port 8000
$ curl localhost:8000/v1/bible/am-1980/JHN/3
{ …, "verses": [ { "n": 1, "geezNumeral": "፩", "text": "…" }, … ],
  "textAvailable": true }
Your license, your responsibility. The CC BY-NC-ND terms (attribution, noncommercial, no derivatives) travel with the text you serve. The API reports the edition's license in every chapter response so downstream consumers see it too. Unknown rights are treated as restricted, never as permission.

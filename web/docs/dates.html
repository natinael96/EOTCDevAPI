Dates & conversion

Describing a day and moving between the calendars. All conversion goes through the Julian Day Number, so the two calendars never need to know about each other.

GET/v1/today

Today, fully described, in a chosen civil timezone.

ParameterRequiredDefaultDescription
tzNoAfrica/Addis_AbabaIANA timezone name used to decide what "today" is
 
$ curl "…/v1/today?tz=Africa/Addis_Ababa"

The response is the timezone plus the complete date description below.

GET/v1/date/{date}

The full description of any date: both calendars, weekday, fasting status, and feasts.

ParameterRequiredDefaultValues
calendarNogregoriangregorian, ethiopian
 
$ curl …/v1/date/2026-04-12
{
  "jdn": 2461143,
  "gregorian": { "date": "2026-04-12", "year": 2026, "month": 4, "day": 12 },
  "ethiopic": {
    "date": "2018-08-04", "year": 2018, "month": 8, "day": 4,
    "monthName": { "amharic": "ሚያዝያ", "translit": "Miyazya" },
    "isLeapYear": false,
    "daysInMonth": 30
  },
  "weekday": { "n": 0, "amharic": "እሑድ", "translit": "Ehud", "english": "Sunday" },
  "fasting": { "isFasting": false, "fastFreeSeason": true, "periods": [] },
  "feasts": [
    { "key": "fasika", "amharic": "ትንሣኤ",
      "english": "Easter (Resurrection)", "movable": true }
  ],
  "commemorations": []
}
  • jdn is the Julian Day Number, a calendar-agnostic integer count of days, useful for date arithmetic on the client.
  • weekday.n is 0 = Sunday through 6 = Saturday, matching JavaScript's Date.getDay().
  • All names come localized (Amharic, transliteration, English) in every response.
GET/v1/convert/{date}

The smaller conversion-only form: JDN, both dates, and the weekday, with no fasting or feast computation. Use it when that's all you need; it's cheaper to read and cache-friendly.

$ curl …/v1/convert/2026-08-27
$ curl "…/v1/convert/2018-12-21?calendar=ethiopian"
POST/v1/calendar/convert/batch

Converts 1–366 non-contiguous dates in one request: a year of birthdays, a list of appointment dates, an arbitrary selection.

$ curl -X POST …/v1/calendar/convert/batch \
    -H "Content-Type: application/json" \
    -d '{ "calendar": "gregorian",
          "dates": ["2026-04-12", "2023-09-11", "invalid"] }'
{
  "calendar": "gregorian",
  "count": 3,
  "results": [
    { "input": "2026-04-12", "jdn": 2461143, "gregorian": { … }, "ethiopic": { … } },
    { "input": "2023-09-11", "jdn": 2460199, "gregorian": { … }, "ethiopic": { … } },
    { "input": "invalid", "error": "Could not parse date 'invalid'." }
  ]
}
Per-item errors. An invalid entry never rejects the valid ones; it receives its own error in place. The whole request fails only when dates is missing, empty, not an array, or longer than 366 elements.

For a contiguous range, prefer /v1/calendar/{year}/{month}: one call per Ethiopian month, fully described.

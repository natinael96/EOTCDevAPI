Data & sources

Infrastructure you can trust has to say what it knows, what it inferred, and what it doesn't have yet. This page is that statement.

Provenance, all the way down¶

Every data directory carries a machine-readable manifest recording title, editor, publisher, edition, scan origin, access date, license status, and hashes. Imported records keep their original source labels next to normalized values — normalization never overwrites source evidence. Where two sources disagree, the conflict is recorded in a reconciliation report instead of silently picking a side.

The licensing boundary¶

  • The API and its bundled data are MIT. Calendar facts, normalized citation metadata, and confirmed-redistributable content only.
  • Bible verse text is not bundled. The local validation editions (am-1980, gez-1980) are CC BY-NC-ND 4.0 — incompatible with MIT redistribution — so the API serves references, never verses.
  • Sinksar narrative text and Gitsawe incipits stay out of the public runtime until their publication rights are recorded. Responses say so explicitly (fullTextAvailable: false with a reason).
  • Unknown rights are treated as restricted, never as permission.

Quality reporting & review queue¶

Data compilation generates public quality reports (data/gitsawe/quality-report.json, data/sinq-gitsawe/quality-report.json) tracking coverage counts, resolved and unresolved Bible books, parsed and incomplete citations, and a structured review queue. Nothing ambiguous is auto-corrected — each open item carries its source coordinates (file, month/day, service, printed label) and waits for evidence:

Open review kindMeaning
incomplete_citationPrinted citation lacks a fully parseable chapter/verse
unresolved_bible_bookA source book label cannot be safely normalized
sinksar_day_heading_mismatchCatalog day and printed summary heading disagree
slot_family_mismatchAn imported reading's book doesn't fit its lectionary slot
chapter_out_of_rangeAn imported citation names a chapter the book doesn't have

Known limitations¶

  1. Daily Gitsawe results are fixed-cycle candidates, not always final service orders.
  2. Movable, Sunday, occasional, and printed Bahire Hasab Gitsawe sections are not yet transcribed; liturgical precedence rules are not implemented.
  3. Regional practice variants are not fully modeled — where reviewed sources disagree, no single custom is claimed as universal.
  4. Bible verse text is not included, by license.
  5. A small structured review queue of source ambiguities remains open (see above) — reported, not guessed at.
  6. Self-hosted Python rate limiting is per-process; use a proxy limiter for fleets.

The API reports incomplete coverage rather than concealing it. That is a feature.

Contributing corrections¶

Corrections to calendar data are especially welcome — feast dates, commemorations, regional variations in fasting practice. Open an issue with a source: identify the edition, cite printed/scan pages, and keep original text separate from the proposed normalization. For code-level changes, both implementations move together: regenerate the shared fixtures (make spec), review the diff — a fixture diff is a behaviour change, and reviewing it is the point — and run make ci.

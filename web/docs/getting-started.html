Getting started

Conventions that apply to every endpoint: dates, calendars, years, timezones, caching, and CORS, plus how to run the API yourself.

Date format & input calendar¶

Dates are always YYYY-MM-DD, in either calendar:

2026-04-12   Gregorian
2018-08-04   Ethiopian, the same day

Endpoints that accept a date default to Gregorian input. Pass an Ethiopian date with the calendar query parameter:

$ curl "…/v1/date/2018-08-04?calendar=ethiopian"

Single-digit month and day inputs are accepted; responses always use zero-padded dates. The alias ethiopic is also accepted, but prefer ethiopian for consistency.

Ethiopian years¶

Year parameters are Amete Mihret (ዓመተ ምሕረት), the ordinary Ethiopian era, roughly the Gregorian year minus seven or eight, depending on the date. Years 1 through 9999 are accepted arithmetically; correctness fixtures emphasize the documented 1800–2200 EC verification range. The broad range is an arithmetic capability, not a claim that historical liturgical practice is uniform across it.

Timezones¶

Only /v1/today needs a timezone; its default is Africa/Addis_Ababa. Values must be valid IANA names (Europe/London, America/Toronto, …).

Common response behaviour¶

Successful /v1/* responses are deterministic for a given input, so they carry a public cache header; rate-limit responses are never cached:

# success
Cache-Control: public, max-age=86400

# 429
Cache-Control: no-store
Retry-After: <seconds>
  • CORS: any origin; GET, POST, OPTIONS.
  • Encoding: JSON is UTF-8; Amharic and Ge'ez text is served without ASCII escaping.
  • Additive fields: new optional fields may appear at any time; parse by name, ignore what you don't know.

Rate limits¶

The public Worker uses a continuously refilling token bucket, plus a coarse Cloudflare edge backstop:

LayerPolicy
Token bucket60-request burst capacity, refilling at 10 requests/second; retry delay computed from the token deficit
Cloudflare backstop600 requests per 60 seconds, edge-local, against sustained abuse

On 429, wait the number of seconds in Retry-After; do not retry in a tight loop. /v1/health is excluded from application rate limiting. See Errors & rate limits for the response shape.

Running it yourself¶

$ git clone https://github.com/natinael96/EOTCDevAPI && cd EOTCDevAPI
$ make setup-check   # verify Node 22 and Python 3.12
$ make install       # both toolchains, locked dependencies
$ make test          # regenerate fixtures, run both suites
$ make dev-ts        # Hono on Workers, locally
$ make dev-py        # FastAPI on :8000, Swagger UI at /docs

The FastAPI app serves interactive OpenAPI documentation at /docs and the schema at /v1/openapi.json. The supported development versions are recorded in .nvmrc and .python-version.

Self-hosted rate limiting

The Python limiter is disabled by default and configured by environment:

VariableDefaultMeaning
EOTC_RATE_CAPACITY0Burst capacity; zero disables application limiting
EOTC_RATE_REFILL_PER_SECOND10Tokens restored each second

The Python limiter is process-local: for multiple workers or hosts, enforce the policy at a trusted reverse proxy instead, and leave capacity unset. The application deliberately does not trust caller-supplied X-Forwarded-For; configure trusted-proxy handling at the server layer so the client address is authoritative.

Or skip the server entirely

The calendar core (ts/src/core/, py/eotc/) has zero dependencies in both languages. Vendor the modules directly into your application if you would rather not make a network call; the same fixtures that hold the two runtimes identical protect your copy too.
